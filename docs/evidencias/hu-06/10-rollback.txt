## Resultado

El pipeline ejecutó `./deploy/rollback.sh dev 0.1.0` y registró el evento `rollback` en
`deploy/releases/dev.json` y en el historial persistente. La etapa terminó SUCCESS.

**Limitación del entorno:** el registry solo tiene publicada la versión `0.1.0`; no existe una
versión anterior real. Para validar el mecanismo se ejecutó el rollback a `0.1.0` (misma versión)
en dev. En un entorno con una versión previa (por ejemplo 0.2.0 → 0.1.0) el mismo script hace el
downgrade real. El registro previo de dev (deploy de `dd825e6`) se conserva en
`dev.json.pre-rollback` y se incluye abajo.

Además, como dev y prod comparten el mismo DinD, el web de prod ocupaba `127.0.0.1:3000`. Se detuvo
temporalmente, se ejecutó el rollback de dev y se reinició; el estado final de prod web es
`Up (healthy)` (ver `12-prod-web-restored.txt`).
