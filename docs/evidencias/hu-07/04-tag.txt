## Corrección aplicada

En el build #18 el tag `v0.2.0` quedó solo local porque `tag-release.sh` comparaba `PUSH_TAG`
contra `1` y Jenkins envía `true` para un parámetro booleano. Además, `github-release.sh` no
enviaba `target_commitish`, así que el GitHub Release inicialmente apuntó al branch por defecto.

Correcciones:

- `deploy/tag-release.sh`: acepta `1`/`true` para publicar; `0`/`false` deja el tag local.
- `deploy/github-release.sh`: agrega `target_commitish` con el commit del tag.

El tag/release se recreó apuntando a `59cec5c`. El tag `v0.2.0` local y remoto coinciden con el
commit de la release.
