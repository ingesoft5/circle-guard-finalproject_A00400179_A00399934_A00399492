## C. Hallazgo: el rol de operación se asume sin un código MFA nuevo
  La sesión de aws login de un usuario que inició sesión con MFA SÍ transmite el contexto MFA, y la
  confianza del rol de operación (aws:MultiFactorAuthPresent y aws:MultiFactorAuthAge < 3600) se
  cumple durante la hora siguiente al inicio de sesión. La conclusión anterior ("aws login no
  transmite MFA") se basó en la raíz cuando aún no tenía MFA y era incorrecta para este caso.
  Consecuencia: el inicio de sesión con MFA en la página de AWS abre una ventana de operación de
  1 h (el código nunca pasa por un proceso local); `unlock` solo sirve para reabrirla después.
  Teardown no se ve afectado: el operador no puede asumirlo (B) y solo el usuario de teardown, con
  MFA de menos de 15 min y desde CloudShell, puede hacerlo.
